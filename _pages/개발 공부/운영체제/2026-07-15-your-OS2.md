# CPU 스케줄링

운영체제는 프로세스들에게 공정하고 합리적으로 CPU 자원을 배분해야한다. 누구는 더 많이 주고, 우선순위를 불공정하고 주면 안된다.

이처럼 운영체제는 **CPU 스케줄링**을 통해서 공정하고 합리적으로 프로세스들에게 CPU 자원을 배분하도록 계획한다.

프로세스의 우선순위는 PCB에 저장하고, 스케줄링 큐를 통해 관리한다.

스케줄링 큐에는 **준비 큐**와 **대기 큐**가 있는데,

**준비 큐**는 CPU를 이용하기 위해 기다리는 줄이라고 생각하면 되고, **대기 큐**는 입출력 장치를 이용하기 위해 기다리는 줄이라 생각하면 된다. 이는 앞서 배운 프로세스의 상태와 같은 개념이다.

스케줄링에는 **선점형 스케줄링**과 **비선점형 스케줄링**이 있는데,
**선점형 스케줄링**은 현재 CPU를 사용 중인 프로세스부터 CPU 자원을 빼앗아 다른 프로세스에 할당하는 것을 말한다.(새치기?)
**비선점형 스케줄링**은 현재 CPU를 사용중인 프로세스의 작업이 끝날 때까지 기다리는 것을 말한다.


## CPU 스케줄링 알고리즘

CPU 스케줄링을 설계할 때는 여러 알고리즘 중 하나를 택해 설계하는데, 다음과 같은 알고리즘이 있다.

1.선입 선처리 스케줄링 

말 그대로 준비 큐에 삽입된 순서대로 처리하는 비선점 스케줄링이다. 들어온 순서대로 처리하고, 비선점 방식이기때문에 프로세스들이 기다리는 시간이 매우 길어질 수 있다는 부작용이 존재한다(호위 효과)

이 또한 마찬가지로 이름대로 CPU 사용이 긴 프로세스는 나중에, 짧은 프로세스 먼저 실행하는 알고리즘이다.

3.라운드 로빈 스케줄링

**라운드 로빈 스케줄링**은 **선입 선처리 스케줄링**과 **타임 슬라이스** 기법을 합친 알고리즘이다. 
여기서 타임 슬라이스란, 각 프로세스가 CPU를 사용할 수 있는 시간을 말한다.
라운드 로빈 스케줄링은 정해진 타임 슬라이스만큼만 돌아가며 CPU를 이용하는 선점형 스케줄링이다.
그래서 사용할 수 있는 시간이 모두 끝난다면 **문맥 교환**을 통해 다음 프로세스가 CPU를 사용할 수 있도록 한다.

4.최소 잔여 시간 우선 스케줄링

**최소 잔여 시간 우선 스케줄링**은 **최단 작업 우선 스케줄링**과 **라운드 로빈 스케줄링**을 합친 스케줄링이다.
정해진 시간만큼 CPU를 사용하되, 다음으로 CPU를 사용할 프로세스로는 남은 작업 시간이 가장 적은 프로세스를 선택한다.

5.우선순위 스케줄링

**우선 순위 스케줄링**은 말 그대로 우선 순위가 높은 프로세스만 실행한다.
그러나 이 방법은 **기아 현상**을 발생 시킬 수 있는데, 이는 우선 순위가 낮은 프로세스는 계속해서 기다리기만 하는 현상을 말한다.
그래서 **에이징**이라는 기법을 통해 기아 현상을 방지하는데, 오랫동안 대기한 프로세스의 우선순위를 점차적으로 높이는 방식이다.

6.다단계 큐 스케줄링

**다단계 큐 스케줄링**은 우선 순위 스케줄링의 발전된 형태로, 우선순위 별로 준비 큐를 여러 개 사용하는 스케줄링 방식이다. 우선 순위가 가장 높은 큐에 있는 프로세스를 먼저 처리하도록 한다. 

그러나 이 방식도 여전히 기아 현상이 발생할 가능성이 존재한다.

# 프로세스 동기화 

프로세스 동기화는 여러 프로세스(스레드)가 **공유 자원**에 접근할 때 발생할 수 있는 문제를 막기 위해 실행 순서를 조율하는 기법이다.

여기에는 **임계 구역**이라는 개념이 있는데, **임계 구역**은 동시에 실행하면 문제가 발생하는 자원에 접근하는 코드 구역을 말한다.

그래서 임계 구역에 진입하고자 하면 진입한 프로세스 이외에는 대기해야하고, 임계 구역에 동시에 접근하면 자원의 일관성이 깨질 수 있다(race condition)

ex) 은행 잔액 1000원에서 두 프로세스가 동시에 100원씩 인출한다 했을때, 프로세스 A,B는 동시에 -100을 하지만 총 잔액이 900으로 남는 현상(race condition)

임계 구역 문제를 해결을 위한 3가지 조건이 있는데, 다음과 같다.

1.상호 배제

한 프로세스가 임계 구역에 진입했다면, 다른 프로세스는 진입 불가

2.진행

임계 구역에 어떤 프로세스도 진입하지 않았다면 진입하고자하는 프로세스는 들어갈 수 있어야함

3.유한 대기

한 프로세스가 임계 구역에 진입하고 싶다면 언젠가는 임계 구역에 들어올 수 있어야함(무한 대기X)

## 동기화 기법

그래서 이러한 문제들을 막기 위해 동기화 기법이 세 가지 존재하는데, 다음과 같다.

1.뮤텍스 락

**뮤텍스 락**은 상호 배제를 위한 동기화 도구이고, 임계 구역을 잠그는 역할로 **acquire** 함수를 사용한다.
이는 프로세스가 임계 구역에 진입하기 전에 호출하고, 임계 구역이 잠겨있다면 열릴 때까지 임계 구역을 반복적으로 확인(busy waiting)하며 열려있다면 임계 구역을 잠그는 역할을 한다.
**release**함수는 임계 구역에서의 작업이 끝나고 호출되고, 현재 잠긴 임계 구역을 여는 역할을 한다.

2.세마포

**세마포**는 좀 더 일반화된 동기화 도구로, 공유 자원이 여러 개 있는 경우에도 적용 가능하다.
임계 구역에 들어가도 되는지 기다려야 하는지 알려주는 **wait** 함수와, 임계 구역 앞에서 기다리는 프로세스에 가도 된다는 신호를 주는 **signal**함수를 사용한다.

여기서도 바쁜 대기가 발생 가능하고, 사용할 수 있는 자원이 없을 경우 대기 상태로 만들고, 생긴다면 대기 큐의 프로세스를 준비 상태로 만든다.

3.모니터

**모니터**는 개발자가 다루기 편리한 동기화 도구이다.
공유 자원에 접근하고자 하는 프로세스를 큐에 삽입하고 삽입된 순서대로 공유 자원을 이용한다.
모니터에서는 조건변수를 이용하는데, 조건 변수는 프로세스나 스레드의 실행 순서를 제어하기 위해 사용하는 특별한 변수를 말한다.
**wait**함수는 프로세스를 대기 상태로 변경하고, 조건 변수에 대한 큐에 삽입을 진행한다.
**signal**함수는 wait()으로 대기 상태로 접어든 조건 변수를 실행 상태로 변경한다.
특정 프로세스가 아직 실행될 조건이 되지 않았을 때에는 **wait**을 통해 실행을 중단시키고, 충족되면 **signal**을 통해 실행을 재개한다.

# 교착 상태

**교착 상태**란 일어나지 않을 사건을 기다리며 진행이 멈춰버리는 현상을 말한다.

이를 확인하기 위해서 자원 할당 그래프를 보곤하는데, 이는 교착 상태 발생 조건을 파악 할 수 있다.

교착 상태가 일어난 그래프는 원의 형태, 즉 사이클이 존재한다.

교착 상태가 발생할 조건에는 4가지가 있는데, 상호 배제, 점유와 대기, 비선점, 원형 대기가 있다. 이 4가지를 모두 만족하면 교착 상태라 할 수 있고, 하나라도 만족하지 않으면 교착 상태는 발생하지 않는다.

**상호 배제**는 한 프로세스가 사용하는 자원을 다른 프로세스가 사용할 수 없는 상태를 말한다.
**점유와 대기**는 자원을 할당 받은 상태에서 다른 자원을 할당 받기를 기다리는 상태를 말한다.
**비선점**은 어떤 프로세스도 다른 프로세스의 자원을 강제로 빼앗지 못하는 상태이고,
**원형 대기**는 프로세스들이 원의 형태로 자원을 대기하는 상태이다. 

## 교착 상태 해결 방법

이러한 교착 상태를 해결하는 방법으론 3가지가 있는데, **예방**,**회피**, **검출 후 회복**이 있다.

1.예방

**예방**은 교착 상태가 발생하지 않도록 교착 상태 발생 조건 중 하나를 없애는 것을 말한다.
이는 교착 상태가 발생하지 않음을 보장할 수 있지만 부작용이 따른다.(자원 활용률 ↓, 시스템 처리량 ↓)

2.회피

**회피**는 교착 상태를 무분별한 자원 할당으로 인해 발생했다고 간주하고 교착 상태가 발생하지 않을 만큼 할당하는 것을 말한다.
교착 상태 없이 모든 프로세스가 자원을 할당 받고 종료될 수 있는 상태인 **안전 상태**를 유지할 수 있는지 확인하고 그렇다면 할당한다.
이 방법은 각 프로세스의 최대 자원 요구량을 알아야하는데, 실제로는 어려운 경우가 많다.

3.검출 후 회복

**검출 후 회복**은 교착 상태의 발생을 인정하고 사후에 조치하는 방식이다.
프로세스가 자원을 요구하면 일단 할당하고, 교착 상태가 검출되면 회복한다.
회복하는 방식에는 **선점을 통한 회복**과 **프로세스 강제 종료를 통한 회복**이 있다.

선점을 통한 회복은 교착 상태가 해결 될 때까지 한 프로세스씩 자원을 몰아주는 방식이고, 프로세스 강제 종료를 통한 회복은 교착 상태에 놓인 프로세스들을 모두 강제 종료하거나, 한 프로세스 씩 강제 종료하는 방식을 말한다. 다만 여기서는 작업 내역을 잃을 위험과 오버헤드가 발생할 가능성이 존재한다.

    showImage(currentIndex);
  };

  nextBtn.onclick = () => {
    currentIndex = (currentIndex + 1) % images.length;
    showImage(currentIndex);
  };

  modal.onclick = (e) => {
    if (e.target === modal) modal.style.display = "none";
  };
});
